三、当前与目标的差异

概念域当前实现需要新增 / 重构边界判断
索引身份VectorIndexMetadata 中有 index UUID、table UUID、location。抽出通用 Index / IndexMetadata / IndexDefinition，vector 只提供具体定义。先保持内部契约，暂不扩大 Iceberg 公共 API。
快照语义有 VectorIndexSnapshot，通过 source-table-snapshot-id 选择索引版本。通用化 IndexSnapshot，增加发布状态、覆盖范围和与 delete/rewrite 的一致性规则。源表 snapshot 是权威；index 不能脱离它宣称有效。
文件层有内部版本化的 tracking/leaf 二进制文件，entry 保存 _file + _pos + vector。抽象通用 TrackingFile / IndexFile / IndexEntry，再决定 Parquet、Puffin 或标准化编码。当前格式是 MVP 实现细节，不应直接当成协议。
查询VectorIndexReader 做 exact linear scan 和跨 leaf top-k。增加通用 IndexQuery、IndexReader、IndexPlanner，支持索引结果与未覆盖文件的混合计划。先保证 correctness，再替换 ANN 执行器。
构建 / refresh只有 leaf/tracking writer，没有从 Iceberg snapshot 构建索引的 builder。IndexBuilder、attempt-scoped 文件、原子发布、增量 refresh、重写和删除处理。这是从“可读原型”到“可用 index layer”的关键缺口。
Catalog / 生命周期metadata 由调用方直接创建，reader 直接接收 metadata 和 FileIO。IndexCatalog、create/list/load/drop/purge，以及 orphan 文件和 retention 管理。Catalog 接入应在通用模型稳定后进行。
引擎接入没有 Spark/Flink planner 或构建入口。增加 engine adapter；core 只保留 engine-agnostic 的 index 语义。遵循 Iceberg 模块边界，不能把 Spark/Flink 依赖带进 core。

四、建议的落地顺序

01 · CONTRACT · 已完成

先定义通用契约

身份、definition、snapshot、coverage、文件引用和 query 结果。已落地：泛化模型 + 静态 registry + parser（index-data-model.html D1–D8）。

02 · ADAPTER · 已完成

把 vector 改成 adapter

保留 COSINE、DOT_PRODUCT、EUCLIDEAN 和 exact search，vector payload 已从通用 metadata 拆入 VectorIndexAdapter（Puffin blob iceberg-vector-entries-v1）。

03 · CORRECTNESS · 下一步

补构建与一致性

从指定 table snapshot 构建，原子发布 manifest / index 文件，沿 parent 血缘做增量 refresh，处理 delete、rewrite、覆盖与未覆盖回退。

04 · INTEGRATION · 待定

再接 Catalog 与引擎

加入 IndexCatalog（sidecar 方案 A 发现）、Spark 构建与 planner；ANN 和 serving runtime 放在语义稳定之后。
