# 索引驻留、容量规划与索引级 LRU 设计

日期：2026-10-24。关联：#2296、#1571；设计工作卡：#2302。

状态：独立 builder check 已完成，唯一重要问题（重复 load 的快照目标替换）已按用户确认补全；等待用户对完整文档的批准，不是实施授权。代码调查基线最初为 `ac59d39a0`，写作文档的独立 worktree 基线为 `ee7447b57`。缓存预算修复正在并行推进，实施前须重新核查，不能按旧调查结果重复修复。

## 1. 目标、理由与范围

大索引不能在每个 executor 放一份。一次手动加载应根据真实可用预算规划，使索引文件在 executor 间尽可能均匀分布。速度不是首要目标；正确性、扩展性和均匀性优先。不要为了避免迁移，永久容忍明显不均。

管理单位是具体 **index**，不是 table 或 column；实际放置单位是 index file。索引缺缓存只影响性能，不改变查询必须覆盖的文件集合。索引文件和元数据仍保存在原存储，驻留命令不修改表数据或删除索引。

### 1.1 用户已确认的规则

- 两条手动命令为 `load_index` 和 `offload_index`。load 触发一次放置规划，不引入定时预热或后台自动重平衡。
- 容量不足仍保留已经加载的部分，明确报告缺口，不整体回滚，也不声称全部加载完成。
- 按 index 独立加载、卸载、管理保护期和访问记录；LRU 因管理粒度的修正而细化到 index。
- 保护期固定计时，查询访问只更新 LRU，不延长保护。到期只是允许淘汰，不立即卸载。
- 首次省略保护期默认 `0`；首次显式传入按该值。重复 load 省略时保留已有策略及原截止时间；显式传入时覆盖策略并从本次调用重新计时。
- `0` 表示立即可淘汰，不是关闭缓存；支持永久保护。新 load 缺空间时优先回收已失去保护、最近未访问的索引。
- 显式 offload 后暂停该索引缓存准入，查询仍可从存储搜索但不驻留，直到下一次 load。
- 构建时逐文件保存带模型版本的驻留内存估计，用于规划；executor 加载时仍检查预算，不把估计当精确堆测量。
- driver 汇总元信息和节点状态，制定计划；executor 侧 SparkPlugin 上报状态、领取定向命令并执行；本地缓存负责保存、预算检查和安全释放。成功必须有实际执行确认。
- 索引刷新后再次 load，以本次捕获的新快照替换旧驻留目标，不累积历次快照。共用文件复用，旧快照独有文件待正在使用的查询结束后释放；保护期不保留所有历史版本，新目标部分加载也不退回旧目标算完成。

### 1.2 本文提出、尚需完整文档批准的设计选择

以下是助手的设计建议，不应误记为用户已经逐项决定：按全节点占用/预算比例均衡；首版每文件一个规划副本；跨索引容量操作串行提交计划；管理状态只在单个 Spark 应用内有效；兼容元数据的版本化格式；受管理索引不允许普通查询任意新增驻留副本；重复 load 可迁移失衡副本；执行协议和结果结构。第 12 节汇总重要选择。

### 1.3 非目标与反目标

不实现跨 Spark 应用共享缓存、driver 状态持久化、跨进程内存共享、后台节点故障修复、自动恢复永久索引、周期均衡、自动预热、TTL 到期主动扫描卸载、多副本高可用或新的搜索算法。插件的状态上报和命令领取不是后台放置调度器。

不能静默漏搜文件；不能靠 locality hint 宣称指定节点已加载；不能突破预算完成预热；不能把已逻辑移除但仍被查询引用的内存当作已释放；不能触碰其他 Agent 的改动或引入未经讨论的依赖。

## 2. 命令与保护策略

建议 SQL 形态如下，参数拼写是本文设计选择：

```sql
CALL catalog.system.load_index(
  table => 'db.t',
  index => 'embedding_hnsw',
  retain_for => '30m'
);

CALL catalog.system.offload_index(
  table => 'db.t',
  index => 'embedding_hnsw'
);
```

`index` 接受索引名或 UUID；匹配存在歧义、索引不属于指定表时拒绝，不能默选第一个。未命名索引可用 UUID 操作。内部使用 table UUID + index UUID，不使用可重命名的表名/索引名作为缓存政策身份。同一列可以有多个索引，列名不是充分身份。

`retain_for` 建议接受 `0`、正整数加单位 `s`/`m`/`h`/`d`，以及 `forever`，单位和值均完整验证，拒绝负值、溢出和不支持的文本。省略与显式 `0` 在解析后仍需可区分。

| 调用 | 结果 |
| --- | --- |
| 首次、省略 | 可淘汰，保护期为 0 |
| 首次、显式有限时长 | 按该时长保护 |
| 首次、显式永久 | 不参与容量驱逐 |
| 重复、省略 | 保留政策和原截止点；已过期不会被续期 |
| 重复、显式 | 替换政策，从本次接受调用的时间重新计时 |

计时建议以 driver 完成参数、身份和快照验证并接受调用的时刻为起点，而不是每个文件完成时分别计时；一次索引调用只有一个保护截止点。有限时长可能在很慢的加载尚未结束时过期。进行中的 load 自身有执行租约，避免同一计划把刚装好的文件自我淘汰；调用终止后只按保护期判断。这个计时选择需随完整文档批准。

`forever` 只是不参加本应用的容量淘汰，不保证 executor 不退出、Spark 应用不结束或硬件不故障。offload 优先于保护，包括永久保护。被拒绝于参数/插件检查的调用不改变政策；被接受但部分失败的调用保留本次政策和已确认副本。后续显式传 0 可解除永久保护。

政策在 driver 中与驻留文件独立保留：即使一次 load 没有加载成功任何文件，或缓存被 LRU 回收，重复省略仍有明确旧策略可继承。offload 保留暂停准入标记；再次 load 恢复准入，省略时仍继承原策略及截止点。

load 开始时捕获与所选 source table snapshot 对应的已发布 index snapshot 和不可变文件清单。无对应索引快照时拒绝，不选一个不覆盖表快照的 latest 代替。构建/刷新不自动触发 load；随后 load 再解析当前快照。旧查询仍使用它捕获的文件清单。

### 2.1 重复 load 的快照目标替换（用户已确认）

每个 index 在本应用只有一个当前驻留目标。重复 load 通过前置验证并被接受时，以本次捕获的 snapshot/file 清单替换旧目标；相同快照则只是重新规划。拒绝于前置验证的调用不切换目标。

新旧目标共有的不可变文件保留逻辑所有权并复用实际副本；旧目标独有文件撤销未来驻留所有权，等已经获取使用引用的搜索结束后释放。使用中的旧文件仍计入占用/待释放，不能先把空间算为空闲。迟到的旧计划命令不能重新建立旧目标所有权。若文件还有其他索引的所有权，只解除本索引所有权，不释放共享物理副本。

旧查询继续搜索自己捕获的完整旧文件清单，未取得或已失去驻留引用的文件可从存储读取并搜索，不保证历史快照继续驻留。有限或永久保护针对当前索引目标，不阻止显式 load 撤销旧快照独有文件；重复调用省略参数仍保留政策与原截止点，显式参数仍按第 2 节更新。

新目标容量不足或部分失败时，保留新目标已经确认的部分并报告新目标缺口；不恢复旧目标，不用历史文件副本声称新目标 COMPLETE。旧文件已无法复用的回收属于目标替换，不是同一文件在两节点间的迁移，因此不要求先把新目标全部加载成功再释放旧独有文件。共有文件的跨节点迁移仍严格遵守先建后删。

## 3. 三层职责与数据边界

### 3.1 driver 协调器

维护索引政策、节点注册/会话、预算和预留快照、实际文件副本、访问记录、计划与命令状态。将 load 拆成按文件的放置命令，offload/LRU 拆成按索引的节点回收命令。选节点、选 LRU victim、处理部分成功都在此层决定。

首版协调器以 Spark application 为边界。相同表在两个应用的保护与缓存互不影响；新 driver/新应用没有旧政策。重启后必须再次显式 load。driver 不接收/转发大文件，不 prepare 全部索引来规划。

### 3.2 executor 侧插件

通过 SparkPlugin 的公共 driver/executor 通道注册、上报并领取命令。周期请求可以携带状态增量和 ACK，响应带发给该 executor 的待执行命令；不要假设有公共 driver 主动推送 API。大命令清单分页/限批，加载在线程数和临时内存约束下异步执行，不能阻塞插件控制通道。

executor 直接使用原 FileIO 从原存储读取文件。命令需包含或引用完整、可验证的读取上下文（索引定义、文件 kind/blob type、读取实现与配置），沿用现有 Spark FileIO 传播方式，不序列化 catalog，不把密钥或文件内容写入状态日志。core 保持 engine-agnostic，SparkPlugin 仅在 index-spark。

### 3.3 本地缓存

统一准入与驻留记账，保护正在使用的 prepared search，支持幂等加载和延迟安全释放，维护实际字节数、预留、引用数、访问序号及政策 epoch。

索引管理信息必须与缓存项建立明确关联。只知道 location 不能执行按索引 offload/LRU。若不可变文件被同一索引的多个快照共享，可共用一份缓存并记录快照引用；若不同索引共享物理文件，offload 只解除该索引的逻辑所有权，所有权/使用引用均清空后才释放物理缓存，不能误卸另一个索引。

## 4. 构建期容量元数据

每个 IndexFile 的 manifest 条目保存可选容量信息，而不是只保存索引总量：实际序列化文件字节数、prepared 驻留估计、估计模型版本、读取/kernel 格式与实现标识、估计环境 profile。精确字段名和二进制编码交给实现计划，但这些概念不能省略。

驻留口径与 `ExecutorIndexCache.loaded(content, prepared).bytes()` 对齐。缓存保留 payload buffer 时计入 buffer，不保留时不重复计入。Puffin 容器字节数与实际保留 payload 长度应分开识别，不能盲目相加。

估计要利用构建中已知的维度、条目数、连接参数、量化参数、实际结构统计等。复用结构模型，不采用全 JVM 构建前后堆差、不把构建峰值当驻留，不为了估计而默认完整反序列化一次刚构建的大索引。不同 builder 的适配方式由实现者决定；新 interface 能力必须提供 default，兼容不提供该信息的旧 adapter。

JVM 引用宽度/对齐、读取实现、HNSW visited pool 的 CPU 规模等会改变估计。profile 至少描述影响当前模型的这些假设。规划器仅直接接受匹配的模型/profile，或由模型显式支持的转换；不兼容时用受支持的结构统计重估。无法重估时做有限并发的 executor 探测，结果同时复用为可确认副本，不能把未知大小当 0，也不能偷偷在 driver 逐个加载大图。探测也必须检查瞬时内存和准入，可拒绝无法安全探测的文件并报告 `SIZE_UNKNOWN`。

旧 manifest 缺少容量字段可读且按上述回退加载；未知模型版本不作为可靠预算依据。当前 manifest 若是不能容纳新增字段的 version 1 二进制结构，新 writer 使用新 manifest 版本，新 reader 同时支持旧版和新版；旧 reader 对新版本明确拒绝而不误解析。不能原位改写已经发布的旧 manifest。index root format 是否需升级由实际格式能力决定，不顺手升级无关格式。

容量信息是规划估计，不是 OOM 上界。executor 加载前预留、加载后核对 retained estimate；不足则该文件不准入并报告。加载峰值包括 read/prepare 临时副本，查询 scratch 与运行时保留区另做资源余量，不用一个驻留数字假装覆盖全部 JVM 内存。

## 5. 状态、访问登记与 LRU

索引记录包含身份、政策、固定截止点、准入状态、最后访问记录、当前计划/政策 epoch；驻留记录按节点和文件列出实际字节数、状态与所有权。节点记录包含 executor ID、注册 incarnation、预算、已占用、已预留、待释放、报表序号和新鲜度。application/driver session 也加入身份，不能把退出后复用的 executor ID 当旧节点。

一次缓存实际被搜索使用时登记索引访问，包括查询最后无结果的情况；只查看状态、读 manifest、预热测量不算搜索访问。新 load 初始化访问记录；重复显式 load 是一次主动使用意图，建议同样更新访问记录，但不把随后状态上报当持续访问。同表另一个索引的访问不更新本索引。

executor 本地登记不需要每次查询同步 RPC，按索引聚合访问增量上报。driver 用最大的新访问记录汇总，不能用“报表接收时间”重置 LRU。可上报相对单调时间年龄及递增访问序号，避免依赖不同机器墙钟完全同步；网络/批处理造成的误差需明确展示。

LRU 是有上报延迟的近似全局顺序，不宣称为所有 executor 所有查询建立严格全序。开始淘汰规划前请求新鲜状态；不响应/过时节点不能用于乐观容量计算。节点尚有活动搜索时可撤销未来驻留所有权，但已使用的内存延迟释放。

候选必须同时满足：非永久、有限保护已到期或0、没有进行中的 load 执行租约。候选按最近访问由旧到新排序，稳定 identity 作平局规则。选择第一个能对本次目标节点腾出所需空间的索引；无法帮助装箱的 victim 不为“腾全局总量”而无意义驱逐。

LRU 的回收动作针对选中索引在本应用的所有驻留节点，回收必要数量的索引后即停止；不按各节点独立文件 LRU 拼出不同索引的残缺集。具体索引自身仍可能因为预算或失败而部分驻留。

## 6. 放置与均匀性

首版每个文件规划一个驻留副本，不主动复制整个索引到每节点。已有非必要重复副本计入实际预算，确认唯一目标副本后再回收多余所有权。相同文件的共享物理副本只记一次空间。

均匀性以节点总占用/预算比例为主，考虑其他索引、预留和余量，而不是平均新索引文件数。容量 B、当前驻留 U、预留 R、运行/加载余量 H 时，可用量为 `max(0, B-U-R-H)`；各字段口径不得重叠计费。预算为0节点不参与。

例如四个相同预算节点已用6、2、2、0 GiB，新增文件优先填后三节点，而不是给四节点等量新增负担。不同预算节点按比例而非绝对字节均衡。

先按估计字节从大到小排列文件；每次选择能容纳文件且预计占用比例最低的节点，平局用稳定节点/文件身份。重复 load 可复用合理副本，但不能用“已有就不动”永久阻止扩容后的均衡。目标优化顺序为可确认覆盖、降低最高占用比例、减少比例偏差，然后才考虑迁移代价。

整文件不可拆分。总预算足够仍可能每台都装不下最大文件，必须报告 `FILE_TOO_LARGE`；总容量不足但部分文件能放时，尽量利用可用空间完成部分驻留。大文件优先是装箱启发式，不承诺数学最优覆盖或绝对相等；实现者可做有界改进，必须保留上述目标顺序与确定性测试。

LRU 回收与放置迭代：先拟定容量缺口，选择可帮助的索引 victim，执行并确认释放，再据新容量生成/修订本次计划。不能把预计释放计为已可用。受保护索引不会因新 load 被整体驱逐；迁移其文件若有独立目的，必须保留至少一个已确认副本。

迁移使用先建后删。没有双份临时空间就暂不迁移，报告无法改善的原因，不先删唯一有效副本强行搬运。执行期间节点容量变化可有界重试/修订本次计划；调用结束后不继续后台修复。

## 7. 命令协议与并发

命令至少带 application session、目标 executor incarnation、index UUID、捕获的 snapshot/file 身份、policy epoch、plan ID、command ID、操作类型和预期容量。执行状态至少区分 queued/reserved/loading/loaded/rejected/failed、evicting/released。最终语义 `loaded` 是本地缓存已发布可用副本的 ACK；`released` 是空间已可重用的 ACK。

节点注册及周期状态有单调序号；重复报表/ACK 不重复计费。命令可能因重试重复送达，executor 按身份幂等处理，driver 保留完成记录到该计划收口。不匹配的 session/incarnation/epoch 拒绝，不允许旧报表把新政策覆盖回去。

首版同应用跨索引的容量规划事务串行：同时到来的 load 可排队，避免两个计划重复预留同一空间或互相驱逐；文件加载在计划内部按节点资源上限并发。参数解析和搜索不拿全局容量锁。offload 可取消/抢占该索引正在执行的 load，不能必须等大索引加载完才处理。

load/offload 同索引采用 driver 接受顺序和递增 epoch；offload 先发布暂停准入的 tombstone，再取消旧命令、撤销所有权和释放。旧 load 即使晚完成，发布缓存前也要检查当前 epoch；过期结果不准入并清理。新 load 恢复准入使用新 epoch，旧 offload 命令不能删除新 load 的副本。

搜索是正常任务路径，但不能带来不受规划的新永久副本。建议对显式管理过的索引：查询只 pin 已有驻留或走不驻留的 read/prepare 搜索，不在非目标节点自行补驻留。未显式管理索引可保留现有懒加载行为，但必须计入节点占用、标记所有权并接受预算检查；首次管理时收编/清理已有副本。该准入边界是本文助手建议，完整文档需用户审阅。

LRU_EVICTED 与 EXPLICIT_OFFLOADED 状态分开：前者仍保留政策和淘汰记录，后者明确暂停准入；两者普通查询都不绕过规划重新填满。首版都通过下一次显式 load 重新规划恢复驻留，不引入查询触发的跨节点重新放置。

offload 和迁移不能影响已获取的搜索引用。释放过程撤销未来 pin/所有权，等待引用归零；期间计入待释放而不是空闲。缓存文件级搜索锁、预算锁、政策锁必须固定顺序，控制线程不得在持有锁时等待网络回复或搜索结束。

## 8. 部分成功、超时和节点变化

load 同步等待到所有文件进入终态或到操作 deadline；deadline、重试次数、上报/命令批量属于实现者可调参数，默认值需在实现计划和测试中具体化，不等同于 retain_for。SQL timeout 不是保护期。

缺插件、索引歧义、无有效快照等前置条件拒绝，不建立新政策；运行中缺容量、读文件失败、prepare 失败、预算估计偏小或节点退出是文件级结果，保留其他已确认文件。超时后取消未完成命令并 fence 旧 epoch，保留确认成功的所有权/政策；取消与晚完成 ACK 必须收口，不能边报告终态边让未统计文件持续回填。

节点退出立即使它的副本不再算作确认覆盖；状态长时间不新鲜则为 unknown，不算安全可用空间。正在执行的本次 load 可在有资源且deadline内修订计划；调用结束后的退出不会触发自动加载。新节点只注册，下次 load 才纳入规划。永久索引丢副本也遵守此边界。

driver/应用退出，政策不持久化，插件停止线程并清理资源。禁止留下独立后台服务。plugin启用与命令注册应是兼容增强：未配置plugin的应用仍可按现有方式查询，但 load/offload 明确报缺少插件，不能退回不可靠 hint 模式假装成功。

## 9. 返回值与可观测性

建议命令返回索引级摘要加逐文件/节点明细：index UUID、捕获快照、policy/plan、状态 COMPLETE/PARTIAL/FAILED/CANCELLED，保护策略及截止点，目标文件数/估计字节数，已确认文件数/驻留字节数，未加载或unknown文件清单及原因，各节点实际与预留/待释放字节数，本次LRU驱逐与迁移列表。

COMPLETE 只在截止核对时目标清单每个文件至少有一个有效 incarnation 上的实际确认副本；PARTIAL 必须显示缺口，不用“任务成功数”或旧 location 报告代替覆盖。运行时字节数也是当前实现的 retained estimate，不对用户标成 heap 实测。

offload 区分准入已暂停与物理释放已完成；操作deadline时有正在使用文件，返回释放待完成明细，不能声明已释放其字节。重试 offload 幂等。状态检查不更新 LRU。

`IndexCacheStatus` 扩展索引身份、准入、保护、访问年龄、新鲜度、真实副本和待释放，复用plugin上报，不只依赖task结束的accumulator和10分钟TTL。指标包括规划/确认偏差、均衡比例、估计/加载后计量偏差、驱逐原因、过期命令拒绝和未知副本；不要泄露FileIO凭证。

## 10. 模块和兼容边界

- `core/.../IndexFile.java`、`IndexManifest.java` 和构建写入链路拥有可选容量元数据；通用模型不引用Spark。
- `index-vector/.../PreparedStructureSize.java`、HNSW/IVF/RaBitQ kernel拥有结构估计、profile及构建统计，不用统一类型乘数替代真实结构差异。
- `index-spark/.../SparkIndexBuilder.java` 传递容量信息；新plugin、driver协调器、procedure和命令协议放在index-spark。
- `ExecutorIndexCache` 拥有准入/预算/引用/epoch，`IndexCacheLocations` 拥有确认副本视图，`DistributedIndexSearch` 和 `IndexFileRDD` 只消费规划/政策，不把hint当强保证。
- `IndexCacheStatus` 对外展示真实状态。搜索完整性测试属于相应所有者模块。

没有已实现的 index_cache_load 可重命名；新命令直接用用户决定的新名字，不新增无意义旧名别名。新公开接口方法要default；不提升package-private可见性，不加入未经讨论的第三方依赖，不写Jackson注解，不改版本目录或受保护配置。

## 11. 验收与验证要求

实现计划必须为以下行为给出直接、可重现测试，而不只是最终吞吐：

1. 同表、同列两个索引，独立load/offload/保护/访问；名字改动不混淆UUID。
2. 首次省略/显式0/有限/永久；重复省略不续期，显式更新重新计时；访问不续保护；到期无容量压力不自动卸载。
3. 可淘汰候选按索引LRU；热点索引不保护同表冷索引；永久和未到期不被驱逐；状态查询不算访问。
4. 四节点等预算和异预算、已有其他占用、预留、整文件不可拆、单文件过大、容量不足、扩容后重复load再均衡。
5. driver规划没有先加载所有大文件；构建容量字段读写兼容旧manifest；未知模型/profile回退；HNSW CPU变化、IVF量化变化和payload留存口径。
6. 实际执行节点与计划一致，重复命令/ACK不重复占用；节点ID复用、过期报表、控制通道超时不会虚构覆盖。
7. 两个load争空间、load与offload抢占、旧命令晚完成、正在搜索时释放、加载峰值配额和预留释放；等待不得死锁。
8. LRU回收、offload和迁移后查询仍搜索全部捕获文件；非归属任务不污染驻留；缓存缺失/节点退出与不缓存路径结果一致。
9. 部分load保留成功文件，结果列出缺口；offload待释放不计为空闲；迁移先建后删且无双份空间不强迁。
10. 应用内启用/未启用插件、应用重启政策不持久化、新节点不自动加载、取消后没有后台回填。
11. 新快照替换目标：共有文件复用，旧独有文件按使用引用延迟释放；永久保护不累积历史；迟到旧命令不回填；新目标部分失败不回滚旧目标，不把旧文件计入新目标覆盖。

真实Spark多executor smoke需验证节点身份/确认、单索引分布、压力下LRU、保护/永久、offload期间查询及节点退出。重新核查#2024修复后再决定补哪些预算测试。文档阶段不跑产品测试；实现阶段按项目规则TDD、独立worktree、重启对应服务并真实smoke，不能以单元测试代替集群执行协议验证。

## 12. 留给实现者及待完整批准的重点

实现者可决定内部类型名、数据结构、方法拆分、命令批量/重试默认值、受支持profile编码、确定性装箱的有界优化和具体测试布局，前提是不改变本文件契约；这些属于随后writing-plans，不在此文档编写代码。

请用户重点审阅助手补充的选择：

- 均衡看全节点占用/预算比例；每文件一个规划副本，重复load允许先建后删迁移。
- Spark应用内管理，不持久化永久政策，不自动修复已结束load的节点故障。
- 从调用接受时间算保护期，加载很慢可能用掉保护期；进行中有独立执行租约。
- 显式管理的索引由load控制驻留，查询miss不自行填充；LRU回收后下一次显式load再恢复。
- 跨索引容量计划串行，同索引offload可抢占；元数据新版本读写兼容和有限executor探测回退。

以上助手选择连同已确认规则，必须在完整设计文档获批后才能进入实施计划。
